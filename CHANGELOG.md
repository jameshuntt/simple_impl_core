# Changelog

## 0.3.2 (2026-10-15)

a `#[composite]` entry now reports every problem in it at once instead of only the first. from_field and from_registry_attr used to return on the first `?`, so a bad kind hid a bad method and a bad method hid a bad init name. now every check after the attr bag runs, each error goes into a SynBuffer, and it only hard fails after all of them. the errors for a bad method, ty or init name say which value was bad and all point at the attribute, and each function has an `_into` version for a caller that already has its own SynBuffer.

### the collector

- from_field bailed on the first `?`: the attr bag, the kind, the method and the init names were each their own early return, so only the first problem ever got reported: [src/composite_model.rs L58-L63](https://github.com/jameshuntt/simple_impl_core/blob/504af2f80c3e32ddb9acf220f995adc00efc8459/src/composite_model.rs#L58-L63). now from_field is a wrapper: new SynBuffer, run from_field_into, then `errs.finish_with(entry)` hard fails with everything folded into one error: [src/composite_model.rs L49-L53](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L49-L53), [liaise_proc_macro src/lib.rs L232-L235](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L232-L235).
- new `from_field_into(field, &mut SynBuffer)` for a caller that collects. kind, method and init each go through `errs.absorb`, so a bad one gets pushed and the next one still runs, and `kind?` only gives up after init was checked: [src/composite_model.rs L64-L68](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L64-L68). the one early stop is an attr bag that doesn't parse at all (L64), since nothing else can be read without it. whenever the kind was read the entry comes back, with the field's own name standing in for a method that didn't parse: [src/composite_model.rs L70-L77](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L70-L77). the contract is in the doc comment, the caller doesn't generate code once anything was reported: [src/composite_model.rs L55-L59](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L55-L59).
- still the field's first `#[composite]`, for parity. the old for loop skipped to the first one and returned from inside the loop: [src/composite_model.rs L53-L56](https://github.com/jameshuntt/simple_impl_core/blob/504af2f80c3e32ddb9acf220f995adc00efc8459/src/composite_model.rs#L53-L56), [src/composite_model.rs L65](https://github.com/jameshuntt/simple_impl_core/blob/504af2f80c3e32ddb9acf220f995adc00efc8459/src/composite_model.rs#L65). now it's a find: [src/composite_model.rs L62](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L62).
- from_registry_attr had the same problem, every step (bag, kind, missing segment, method, ty, init) was an early return: [src/composite_model.rs L89-L105](https://github.com/jameshuntt/simple_impl_core/blob/504af2f80c3e32ddb9acf220f995adc00efc8459/src/composite_model.rs#L89-L105). now it's the same wrapper, [src/composite_model.rs L86-L90](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L86-L90), over the new from_registry_attr_into, same contract: [src/composite_model.rs L92-L97](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L92-L97). a missing command/surface value gets pushed instead of returned: [src/composite_model.rs L104-L111](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L104-L111). same for a missing `ty =`: [src/composite_model.rs L128-L131](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L128-L131). the entry still comes back with stand-ins (`__simple_impl_unnamed_entry` for the method, an empty segment, `()` for ty) so the caller can keep checking the rest: [src/composite_model.rs L140-L142](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L140-L142).

- `ty`: same thing with `syn::parse_str::<Type>(ty_tokens)?`: [src/composite_model.rs L103](https://github.com/jameshuntt/simple_impl_core/blob/504af2f80c3e32ddb9acf220f995adc00efc8459/src/composite_model.rs#L103). now it's at the attribute and says `ty = X` is not a type: [src/composite_model.rs L124-L126](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L124-L126).
- `init = "a, b"`: the old `.collect()` into a Result stopped at the first bad name and didn't say which one it was: [src/composite_model.rs L214-L221](https://github.com/jameshuntt/simple_impl_core/blob/504af2f80c3e32ddb9acf220f995adc00efc8459/src/composite_model.rs#L214-L221). now it goes through collect_all, so every bad name gets reported, each by name: [src/composite_model.rs L242-L252](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L242-L252). collect_all is the collecting form of `.collect::<Result<Vec<_>, _>>()` in liaise_proc_macro: [liaise_proc_macro src/lib.rs L178-L185](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L178-L185).
- when an init name is bad, parse_init_args_into still hands back one stand-in (`__simple_impl_unnamed_init`) so "init was written" holds for the checks that only need that: [src/composite_model.rs L254-L262](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L254-L262). both `_into` functions use it: [src/composite_model.rs L67](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L67), [src/composite_model.rs L135](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/src/composite_model.rs#L135).

### CI

- new `.github/workflows/ci.yml`. it runs on every push and pull request: [.github/workflows/ci.yml L7-L9](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L7-L9). the test job is a matrix of stable and 1.85 (the rust-version floor) with fail-fast off, `cargo test --all-features` on both: [.github/workflows/ci.yml L23-L26](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L23-L26), [.github/workflows/ci.yml L41-L46](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L41-L46).
- liaise_proc_macro and simple_impl_attr_kit are path deps, so CI clones them into `../<name>` first, on the same branch name when the sibling has one so a change across crates gets tested together, otherwise its default branch: [.github/workflows/ci.yml L16-L17](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L16-L17), [.github/workflows/ci.yml L29-L37](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L29-L37).
- the publish job only runs on a push to main after test passes, one at a time (`concurrency: publish`), and it's the only job with `id-token: write`, for crates.io trusted publishing, so there's no stored token: [.github/workflows/ci.yml L48-L55](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L48-L55), [.github/workflows/ci.yml L78-L84](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L78-L84).
- before publishing it asks crates.io about this name and version: 200 means it's already there and it skips, 404 means it's new and it publishes, anything else fails the job: [.github/workflows/ci.yml L68-L77](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L68-L77).
- it won't publish with uncommitted changes besides Cargo.lock (the lock can drift because the cloned siblings are at other versions), which is why `cargo publish` gets `--allow-dirty`: [.github/workflows/ci.yml L86-L91](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L86-L91), [.github/workflows/ci.yml L96](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L96).
- crates released together publish in dependency order, so when cargo publish fails because a dependency isn't on crates.io yet it waits 30s and tries again, up to 30 times. any other failure stops it: [.github/workflows/ci.yml L92-L102](https://github.com/jameshuntt/simple_impl_core/blob/28fb53a4ffcb695c88fb93f0bb49548463b95fdc/.github/workflows/ci.yml#L92-L102).
